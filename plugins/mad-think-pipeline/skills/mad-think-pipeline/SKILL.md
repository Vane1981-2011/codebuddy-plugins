# mad-think-pipeline v2.0 — 深度推理管线

> 继承 zcode v1.0 核心管线结构，融合智能体平台思维方法论。
> v1.0 → v2.0：从"单线推理"升级为"多路径并行推理 + 交叉验证 + 合成输出"。

---

## 一、管线架构（v1.0 核心结构保留）

```
INPUT（复杂问题 / 模糊需求 / 重大决策）
    │
    ▼
┌─────────────────────────────────────────┐
│  S1 问题拆解 (Task Decompose)            │  ← 方法论：准备阶段
│  ─ 还原底层需求 vs 表面需求              │
│  ─ 拆解为独立子问题（3-7 个）            │
│  ─ 标注依赖关系与执行顺序               │
│  ─ 为每个子问题指定所需推理类型          │
└──────────────┬──────────────────────────┘
               │ 子问题列表 + 依赖图
               ▼
┌─────────────────────────────────────────┐
│  S2 并行推理 (Parallel Reason)           │  ← 方法论：执行阶段
│  ─ 每个子问题分派独立推理路径            │
│  ─ 多模型路由（推理/代码/创意/轻量）     │
│  ─ 每条路径独立推演至结论               │
│  ─ 记录中间推理步骤和置信度             │
└──────────────┬──────────────────────────┘
               │ 各路径结论 + 置信度
               ▼
┌─────────────────────────────────────────┐
│  S3 交叉验证 (Cross-Verify)              │  ← 方法论：质检阶段
│  ─ 多路径结论互相验证（一致性检查）     │
│  ─ 冲突检测 → 标记 + 回溯重新推理       │
│  ─ 遗漏检查 → "我漏了什么？"自检        │
│  ─ 不确定性量化 → 每结论标注置信度      │
└──────────────┬──────────────────────────┘
               │ 验证后结论集
               ▼
┌─────────────────────────────────────────┐
│  S4 合成输出 (Synthesize)                │  ← 方法论：复盘阶段
│  ─ 多路径结论合成为统一方案              │
│  ─ 标注方案中的假设和不确定性            │
│  ─ 产出可操作决策建议                   │
│  ─ 触发反馈缝合（Memory + 反模式归档）  │
└──────────────┬──────────────────────────┘
               │
               ▼
            OUTPUT（结构化方案 + 置信度矩阵 + 决策建议）
```

## 二、四阶段执行协议

### S1：问题拆解 — 从"一个问题"到"一组可并行推理的子问题"

**输入**：用户的复杂问题或模糊需求

**执行步骤**：
1. **需求还原**：区分"表面需求"和"底层需求"（加载 real-needs-classifier 卡片）
2. **结构化拆解**：
   - 识别问题的独立维度（技术/业务/成本/风险/时间）
   - 将每个维度拆解为独立子问题
   - 标注子问题之间的依赖关系
3. **推理类型匹配**：

| 子问题类型 | 推理方式 | 推荐模型 | 置信度策略 |
|-----------|---------|---------|-----------|
| 事实查询 | 工具获取（WebSearch/Read） | lite | 高置信度（可验证） |
| 逻辑推演 | 链式推理（L2） | reasoning | 中置信度（需验证前提） |
| 因果分析 | 反事实推演 | reasoning | 中置信度 |
| 价值判断 | 多视角对比（L2多路径） | default | 低置信度（标注为判断） |
| 创新方案 | 第一性原理重构（L1） | reasoning | 低置信度（标注为探索） |
| 风险评估 | 死亡清单扫描 | default | 高置信度（结构化检查） |

4. **输出格式**：

```json
{
  "root_question": "...",
  "underlying_need": "...",
  "sub_questions": [
    {
      "id": "SQ-1",
      "question": "...",
      "type": "fact_query",
      "reasoning_method": "tool_fetch",
      "model": "lite",
      "depends_on": [],
      "priority": 1
    }
  ],
  "dependency_graph": { "SQ-2": ["SQ-1"], "SQ-3": ["SQ-1", "SQ-2"] }
}
```

### S2：并行推理 — 多路径同时推演

**输入**：S1 产生的子问题列表 + 依赖图

**执行步骤**：
1. **并行分派**：无依赖的子问题通过 Agent 工具并行启动
2. **每条路径模板**：

```
子问题 ID: {id}
推理方法：{method}
---
Step 1: 前提确认 — 该问题的隐含假设是什么？
Step 2: 路径推演 — 基于假设 A → 推出结论 A1
Step 3: 替代路径 — 如果假设不成立 → 替代结论 B1
Step 4: 置信度标注 — [高/中/低] + 理由
Step 5: 依赖传递 — 本结论影响哪些下游子问题？
```

3. **死锁检测**：如果子问题 A 等待 B，B 等待 A → 打破循环，使用 L1 第一性原理独立推理
4. **中间结论缓存**：每条路径的输出缓存到结构化变量，供 S3 直接消费

### S3：交叉验证 — 多路径结论互校

**执行步骤**：
1. **一致性矩阵**：构建 N×N 矩阵，检查每对结论的一致性
2. **冲突处理**：

| 冲突类型 | 处理方式 |
|---------|---------|
| 事实冲突 | 回退到工具层重新获取事实 |
| 逻辑冲突 | 检查中间步骤，标注分歧点 |
| 假设冲突 | 明确标注假设差异，保留两版 |
| 置信度冲突 | 高置信度结论优先，低置信度结论降权 |

3. **遗漏自检**：
   - "我漏掉了什么维度？"
   - "反向假设推翻我的结论？"
   - "边界条件是否覆盖？"

4. **不确定性输出**：对每个子问题结论标注不确定性来源和替代可能性

### S4：合成输出 — 统一方案生成

**执行步骤**：
1. **结论聚合**：将验证后的子结论合并为统一叙事
2. **结构输出**：

```
## 结论（1 句话）

## 推理过程
  - 子问题 1 → 结论 + 置信度
  - 子问题 2 → 结论 + 置信度
  - ...

## 关键假设
  - 假设 A：...
  - 假设 B：...

## 不确定性标注
  - 低置信度节点：...（替代可能性：...）
  - 依赖的外部信息：...

## 决策建议（3 个选项，按优先级排序）

## 风险提示
```

3. **反馈缝合**：
   - 写入 Memory（结构化事件）
   - 如有新发现的反模式 → 归档到 anti-patterns.yaml
   - 记录 τ_decide / τ_execute

## 三、工具调用编排（v2.0 新增）

### Agent 分派矩阵

| 子任务类型 | Agent 类型 | 工具 | 模型 |
|-----------|-----------|------|------|
| 事实查找 | Explore (quick) | WebSearch, WebFetch, Read | lite |
| 代码分析 | Explore (medium) | Grep, Glob, Read | default |
| 深度推理 | general-purpose | 全工具 | reasoning |
| 数据聚合 | Bash 脚本 | python3, grep | — |
| 内容生成 | 多模态 Skill | ImageGen, VideoGen | — |

### 并行度控制

| 场景 | 并行策略 | 最大并发 |
|------|---------|---------|
| 完全独立子问题 | 全部并行 | 5 |
| 部分依赖 | 按依赖层级分批 | 3/批 |
| 高度依赖 | 串行（每步验证后推进） | 1 |
