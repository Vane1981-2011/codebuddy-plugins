# 跨对话上下文管理器

管理 `~/Desktop/WorkBuddy上下文/上下文文档.md`，确保跨对话的信息衔接与连续性。

## 文档结构

上下文文档包含四个模块，均有清晰层级和时间戳标记：

| 模块 | 用途 |
|------|------|
| 一、任务概述 | 当前项目/主题列表、核心目标、关键约束 |
| 二、历史记录 | 按日期排列的事件日志（决策/进展/问题） |
| 三、当前状态 | 进行中任务、待决策事项、已知问题与风险 |
| 四、下一步计划 | 短期（本周）、中期（本月）、长期 |

## 对话启动读取协议

每次新对话启动时，按以下步骤加载上下文：

1. 读取 `~/Desktop/WorkBuddy上下文/上下文文档.md`
2. 提取「一、任务概述」中所有活跃项目及其状态
3. 提取「三、当前状态」中的进行中任务和待决策事项
4. 提取「四、下一步计划」中的短期计划
5. 将提取的信息作为当前对话的上下文基础，确保不偏离既有主题

若文档不存在或为空，告知用户并初始化。

## 对话结束更新协议

每次对话结束（用户确认任务完成、或对话自然终止转向新对话）前，按以下步骤更新文档：

1. 读取 `~/Desktop/WorkBuddy上下文/上下文文档.md` 获取当前内容
2. 在「二、历史记录」中追加当日条目：

```
| HH:MM | 类型(决策/进展/问题) | 内容摘要 |
```

3. 更新「三、当前状态」：
   - 已完成任务 → 标记完成或移除
   - 新产生的待办 → 追加
   - 新产生的待决策事项 → 追加
   - 已知问题与风险 → 更新

4. 更新「四、下一步计划」：
   - 当前对话中产生的新任务 → 追加到短期/中期/长期
   - 已确认变更的计划 → 更新

5. 更新文档顶部的「最后更新」时间戳

## 更新规则

- 仅记录有追溯价值的信息（任务进展、重大决策、未解决问题）
- 避免记录临时性、一次性、无复用价值的操作细节
- 每个条目包含时间戳标记（精确到分钟）
- 已完成的任务从「当前状态」中移除，保留在「历史记录」的日志中
